# ACVPN для Windows

[English](README.md) | **Русский**

ACVPN — приложение для подключения к вашим серверам и подпискам через локальный прокси на Windows. Приложение не предоставляет серверы или подписки: их необходимо получить у провайдера или настроить самостоятельно.

## Возможности

- Импорт отдельных конфигураций и HTTPS-подписок, обновление подписок.
- Поиск и сортировка серверов, список избранного, проверка задержки и сертификатов.
- Системный прокси Windows или ручная настройка локального HTTP/SOCKS5-прокси.
- Правила для сайтов и приложений: напрямую, через прокси или блокировать.
- Автоматическая проверка обновлений установленного приложения.
- Русский и английский языки, светлая и тёмная темы, работа в системном трее.

## Установка и подключение

1. Скачайте установщик из [релизов GitHub](https://github.com/kameker/ACVPN/releases) и запустите его. Неподписанная сборка может вызвать предупреждение Windows об издателе.
2. Нажмите «Добавить» и вставьте ссылку конфигурации или HTTPS-ссылку подписки.
3. Выберите сервер и нажмите кнопку подключения.
4. Для отключения нажмите кнопку ещё раз. Закрытие окна сворачивает приложение в трей; для полного выхода используйте меню значка в трее.

По умолчанию ACVPN настраивает системный прокси Windows. Через него работают приложения, использующие системные настройки; программы, которые их игнорируют, автоматически перенаправлены не будут. В настройках можно отключить системный режим и вручную указать в нужной программе HTTP- или SOCKS5-прокси `127.0.0.1:2080`.

При обычном отключении ACVPN восстанавливает прежние настройки прокси, если они не были изменены другой программой. При аварийном завершении восстановление предпринимается при следующем запуске.

## Серверы и подписки

«Чек пинг» измеряет время прямого TCP-соединения с сервером и запускает проверку обычного TLS-сертификата через сервер с подключением к `www.cloudflare.com:443`. Проверка раскрывает факт подключения VPN-серверу и Cloudflare. Сетевые ошибки и ошибки сертификата показываются отдельно; для Reality, соединений без TLS и с отключённой проверкой предусмотрены отдельные статусы. Проверенный сертификат не гарантирует работоспособность сервера, а задержка не измеряет скорость соединения.

По умолчанию серверы и избранное сортируются по пингу: сначала идут серверы с измеренной задержкой и проверенным сертификатом, затем подходящие серверы без обычного TLS-сертификата; остальные остаются видны ниже. Страна определяется по названию сервера, а не по его IP. При выборе другого сервера во время подключения приложение переключается на него.

Кнопка «Обновить» обновляет подписки; перед обновлением необходимо отключиться и дождаться окончания проверки серверов. Управление отдельными подписками доступно в режиме сортировки «По подпискам».

Некоторые провайдеры требуют идентификатор устройства. При добавлении подписки можно разрешить его передачу: для этой ссылки ACVPN отправляет постоянный случайный `X-HWID`, название и версию ОС и имя пользователя в формате `ОС-пользователь`. Провайдер может засчитать его как отдельное устройство, а отображение имени зависит от провайдера. Идентификатор и разрешения хранятся локально в зашифрованном виде. Если провайдер вернул только заглушку «App not supported», сохранённые серверы ею не заменяются.

## Маршрутизация и ограничения

- Поддерживаются URI VLESS, VMess (base64 JSON), Trojan, Shadowsocks (SIP002) и SOCKS5; подписки могут содержать список URI в обычном виде или base64. Неподдерживаемые строки пропускаются; импорт отклоняется, если поддерживаемых строк нет.
- Для соответствующих ссылок поддерживаются VLESS Reality и TLS, TCP, WebSocket и gRPC. Не все параметры провайдеров поддерживаются; Hysteria2, Shadowsocks-плагины, прямой импорт JSON, файлов и QR-кодов не реализованы.
- Правила сайтов применяются только к трафику, поступившему в локальный прокси; доменные правила включают поддомены. Правила приложений сопоставляют полный путь `.exe` и проверяются раньше правил сайтов. Приложение можно выбрать среди запущенных процессов или указать путь вручную. Изменения правил вступают в силу после переподключения.
- Системный прокси не обеспечивает перенаправление всего трафика: UDP и DNS могут идти напрямую. Kill switch, защита от утечек, собственная настройка DNS, проверка внешнего IP и автоматическое восстановление после потери сети не реализованы.
- Существующие исключения Windows и автоматическое обнаружение прокси могут влиять на маршрутизацию. Если в Windows задан PAC URL, включение системного режима отклоняется.
- Статус «Прокси запущен» означает, что запущен sing-box и отвечает локальный порт. Он не подтверждает аутентификацию, доступность удалённого сервера или отсутствие утечек. Локальный прокси без аутентификации доступен другим процессам на этом компьютере.
- При переключении серверов соединение прерывается, и без kill switch возможен прямой доступ. После аварийного завершения приложения системный прокси может оставаться включённым до следующего запуска ACVPN; процесс ядра в отдельных случаях может потребовать ручного завершения.

## Данные и обновления

Настройки, конфигурации и ссылки подписок хранятся в зашифрованном файле `data.enc` в каталоге пользовательских данных Electron. Шифрование использует Electron `safeStorage` и Windows DPAPI. Конфигурация передаётся sing-box через стандартный ввод; во время работы данные доступны процессам той же учётной записи. Аналитика отсутствует.

HTTPS-подписки загружаются по указанному адресу без перенаправлений; размер ответа ограничен 2 МБ. Установленная версия проверяет публичные релизы GitHub при запуске и периодически во время работы. Обновление загружается автоматически и устанавливается после отключения прокси и восстановления настроек Windows. Ручная проверка доступна в настройках. Установки без механизма обновлений необходимо обновить вручную один раз. Для неподписанных сборок подлинность издателя не подтверждается цифровой подписью.

## Разработка и сборка

Для сборки требуется Windows, Node.js и npm. В CI используется Node.js 24.13.1:

```powershell
npm ci
npm test
npm start
npm run dist
```

Установщик создаётся в `dist/`; локальную распакованную сборку можно запустить из `dist/win-unpacked/ACVPN.exe`. Тесты проверяют обработку данных, конфигурации sing-box, маршрутизацию и проверку TLS с локальными тестовыми серверами. Пользовательский сервер или подписка в тесты не входят.

[GitHub Actions](https://github.com/kameker/ACVPN/actions/workflows/windows-build.yml) устанавливает зависимости, запускает тесты и собирает Windows-установщик при изменениях в `main`, для pull request и по ручному запуску. Результат сохраняется как артефакт `ACVPN-Windows-unsigned` на 14 дней. Этот процесс не подписывает установщик и не публикует релиз.

### Цифровая подпись Windows

Для обязательного подписания при сборке выполните `npx electron-builder --win nsis --config.forceCodeSigning=true`: без настроенного ключа сборка завершится с ошибкой. Для доверенной подписи необходим действующий сертификат Code Signing с доступным закрытым ключом. Если поставщик допускает файл `.pfx` или `.p12`, укажите путь в `WIN_CSC_LINK`, а пароль — в `WIN_CSC_KEY_PASSWORD` в локальной среде. Для токена или облачного ключа следуйте инструкциям поставщика. Не добавляйте ключи и пароли в репозиторий.

После сборки проверьте установщик и основной `ACVPN.exe` командой PowerShell `Get-AuthenticodeSignature`: статус должен быть `Valid`. Подпись не гарантирует немедленного исчезновения предупреждений SmartScreen. Подписание через SignPath требует отдельного одобрения и настройки.
